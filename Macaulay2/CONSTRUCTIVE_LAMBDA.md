# Constructive search for a sparse `Lambda`

## What the code certifies

Let `R` be the operator matrix in a Weyl algebra and let `Lambda` be a
`q`-by-`r` augmentation, where `q = numRows R`.  The convention in the code
is

```text
P = R | (-Lambda)
```

For a candidate `P`, Macaulay2 computes

```text
B          = Dtransposition mingens image syz Dtransposition P
recoveredP = transpose mingens image syz transpose B
```

The certificate has three separate fields:

1. `relationZero` checks the direct identity
   `transpose B * transpose P == 0`.
2. `exact` checks both module inclusions between the columns of
   `transpose P` and `transpose recoveredP`.  This is the exact
   double-annihilator/presentation check used by the existing GhostTasking
   calculations.
3. `surjective` checks whether `image P` is the whole target free module.
   This is a stronger splitting/unimodularity certificate and is reported
   separately; it is not silently conflated with exactness.

The relation matrix is intentionally called `B`, rather than `Q`: after the
formal Weyl-algebra transposition it represents the relation module, not a
literal matrix satisfying `P*Q == 0` in Macaulay2's left-module convention.

## What is constructive

`searchLambda(R, operators, maxColumns)` enumerates all nonzero columns whose
entries are drawn from the finite, ordered list `operators`.  It tests every
one-column candidate first, then every two-column candidate, and stops at the
first exact certificate.  Thus the search is exhaustive and reproducible
inside the declared ansatz.  A failed search is not a no-go theorem outside
that ansatz.

The identity baseline is always available as `Lambda = id_(target R)`.  It is
deliberately not treated as a discovery: it uses `q` augmentation columns and
is only a control showing that the exact and surjective tests behave as
expected.  The regression examples find one-column, non-identity candidates.

| example | finite operator list | candidates | tested | columns found | exact | surjective |
| --- | --- | ---: | ---: | ---: | --- | --- |
| pedagogical PDE | `0, 1, dt` | 9 | 1 | 1 | yes | no |
| tripendulum ODE | `0, 1, dt, t, l, l*dt, l*t` | 343 | 10 | 1 | yes | no |
| magnetostatics PDE | `0, 1, -1` | 27 | 3 | 1 | yes | no |

The `surjective = no` result is useful evidence, not a failure hidden by the
test: the sparse candidates are genuinely different from the identity
fallback, while the stronger splitting property remains a separate question.

Run the regression oracle from the repository root with:

```bash
python tests/test_constructive_lambda.py
```

It launches a separate Macaulay2 process and checks both the emitted test
markers and the direct relation identities.

## Why this is the right theory-level reduction

For a finitely presented differential module `M`, the Serre-reduction
formulation identifies the obstruction with an `Ext^1` module.  In the usual
operator convention it has the form

```text
ext^1_D(M,D) = D^q / (R D^p)
```

The one-column GhostTasking construction is possible when this obstruction is
cyclic and generated by the class of `Lambda`; the two-column result follows
from the two-generator theorem for finitely generated torsion modules over a
Weyl algebra.  The finite search above is therefore a concrete generator
search for the missing class, followed by an exact Weyl-algebra certificate.

The literature does not provide a turnkey Macaulay2 command that takes an
arbitrary presented module and returns this `Ext^1` generator.  Macaulay2's
`stafford` command is for ideals and documents a rational-function-extension
caveat.  The present code fills the reproducible gap needed by these
examples: it makes the ansatz explicit, searches it completely, and verifies
the result over the original Weyl algebra.  It does not claim that failure of
a bounded search disproves Stafford's theorem.
